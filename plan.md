# Motor B / motorbreif Vehicle Reports — Implementation Plan

## Scope and current architecture

Recreate and evolve the supplied MOTORA website while preserving its React 18/Vite client, Node/Express server, responsive automotive editorial design, registration lookup, pricing, terms and report workflows. The public identity is now **Motor B** with **motorbreif** as the accompanying descriptor. The Node server serves the built site and JSON API from one configured listener.

The frontend uses React and CSS in `client/src/`; the Express backend lives in `server/`. UKVD credentials are runtime-only server secrets. Stripe secrets and webhook signing credentials are managed through the supported project integration and are never stored in source, browser bundles, logs or chat. Managed MySQL provides durable report and Stripe-event records. SMTP remains optional; email failures must not block a paid report.

## Existing vehicle-report behavior

The single standard vehicle report is priced at **£9.99**. The server creates Checkout Sessions, validates normalized UK registrations, verifies completed paid sessions in GBP and the correct product marker, and assembles reports using UKVD `VehicleData` and `MotHistoryData`. The stored report retains the full provider response groups; refreshes reuse reports keyed by Checkout Session ID. Stripe webhook signatures are verified against raw request bytes and event IDs are recorded so duplicate deliveries are no-ops. Receipts, report retries and printable A4/PDF layout are part of the report experience. Existing paid sessions using legacy MotorBrief/MOTORA markers remain compatible.

Production Stripe initialization accepts only a live `sk_live_` or permissioned `rk_live_` server secret. A successful test or code build is not evidence that production Checkout is enabled. The owner supplies live credentials only through the supported Dashboard integration flow; never copy secrets from chat or development to production.

## UKVD coverage and disclosure

The current backend requests only `VehicleData` and `MotHistoryData`. It does not currently request VDI Check, damage, service-history, advertising-history, or other optional packages. The homepage groups requested fields and labels data/package availability accurately; it must not promise that categories outside the active integration are live. CO₂, Euro rating, tax values, technical fields and other details are displayed from the provider response when actually returned.

UKVD's documentation defines data packages and describes VDI Check as a distinct service with finance, write-off, stolen, recall and technical/provenance fields. Do not add an optional package or per-lookup cost unless the owner confirms that the account supports it and explicitly authorizes the cost. Sources: [UKVD data packages](https://ukvehicledata.co.uk/apidocumentation?Doc=DataPackages), [VDI Check](https://ukvehicledata.co.uk/VDI-Check), [UKVD pricing](https://ukvehicledata.co.uk/pricing), [GOV.UK CO₂ and vehicle-tax data](https://www.gov.uk/co2-and-vehicle-tax-tools).

## EV comparison feature

The homepage EV section presents three report tiers. **Essential comparison — £4.99 (Launch offer):** two EVs, specifications, range, charging and motor details. **EV Buyer Intelligence — £7.99 (Recommended):** up to three EVs, personalized running costs, three- and five-year ownership estimates, resale scenarios and a buying checklist. **Premium Used EV Report — £12.99:** vehicle-specific history and battery analysis only when supported by licensed data sources. The £35,000 amount is an example purchase price, not a minimum. Optional customer-entered asking prices are listing figures, not valuations. Only the Essential tier receives a Preview-only Stripe test-mode Checkout; it must never create a live charge or UKVD lookup, and a verified test order is explicitly not a generated report or commercial fulfillment.

The EV comparison report design uses model/reference specifications only where supported and returned: make/model/year and BEV/PHEV type; battery capacity; range; charge connectors/locations, power and time; motor power/torque; efficiency; and manufacturer battery warranty. It must show missing fields rather than inventing values or a single winner. Explicitly state that model data does not measure a specific used vehicle's traction-battery state of health, real-world range or physical condition.

UKVD's [EV Data](https://ukvehicledata.co.uk/EV-Data) and [Electric Vehicle Details source](https://vehicledataglobal.com/DataSources/ElectricVehicleDetails) pages describe EV/model data for supported BEV/PHEV vehicles. The separate [Battery Details source](https://vehicledataglobal.com/DataSources/BatteryDetails) concerns starter-battery matching, not used-EV traction-battery health. Confirm live-account access, exact `DataPackage`/`PackageId`, response shape and costs with UKVD before enabling customer lookup. Do not bundle paid VDI Check into any EV tier without a separate owner decision.

A reusable full report template is routed at `/ev-report`, linked from the EV section as `/ev-report?demo=1`. It presents a clearly fictional sample with two vehicles, selected priority, a neutral buyer summary and dealer handoff note. Its print action generates a report-only A4/PDF layout. It is sample design only: no live lookup, payment or actual vehicle data.
